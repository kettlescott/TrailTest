## CPU Duration-Controlled Workload Implementation

### Summary
Implemented time-based CPU workload execution using the same mechanism as MEMORY duration-controlled mode.

### Files Changed
1. **CpuBoundWorkloadDuration.java** (NEW)
   - Duration-controlled CPU workload class
   - Executes CPU-intensive mixing function for target duration
   - Batch-based deadline checking (amortizes nanoTime cost)

2. **TaskGenerator.java**
   - Extended EntryState with cpuTargetMicros, cpuMode fields
   - Modified createWorkload() to instantiate CpuBoundWorkloadDuration
   - Updated Calibration record with CPU duration-controlled fields
   - Updated summary() method to display CPU duration mode

3. **WorkloadEntry.java**
   - Updated validation to allow CPU + targetMicros
   - targetMicros now valid for both CPU and MEMORY workloads

4. **CpuDurationControlledTest.java** (NEW)
   - 11 comprehensive unit tests
   - Tests accuracy for 50µs, 100µs, 200µs targets
   - Tests YAML parsing and config loading
   - Tests backward compatibility with fixed iterations
   - All tests passing

### Configuration Examples

**Duration-controlled CPU (NEW)**:
```yaml
workloads:
  cpu_200us:
    - kind: CPU
      targetMicros: 200    # ← Time-based
      ratio: 1.0
```

**Fixed-iteration CPU (Legacy - still works)**:
```yaml
workloads:
  cpu_200us:
    - kind: CPU
      cpuIterations: 64000 # ← Iteration-based (backward compatible)
      ratio: 1.0
```

### Key Implementation Details
- Uses batch-based loop with deadline checking
- Batch size: 100 iterations per check
- Actual execution time will exceed target by at most one batch duration
- Deterministic mixing function (XOR-shift + golden-ratio)
- No locks, blocking, or I/O

### Batch Size Tuning
- Current: 100 iterations per batch
- For 50µs target: ~10-20% overshoot
- For 100µs target: ~5-10% overshoot
- For 200µs+ target: ~3-5% overshoot

### Execution Mechanism
CPU Duration-Controlled follows MEMORY pattern:

```
long start = System.nanoTime();
while (elapsed < targetNanos) {
    // Perform batch of CPU work
    for (int i = 0; i < batchSize; i++) {
        x ^= (x << 13);
        x ^= (x >>> 7);
        x ^= (x << 17);
        x = x * 0x9E3779B97F4A7C15L + counter;
    }
    // Check deadline only after batch
    elapsed = System.nanoTime() - start;
}
```

### Backward Compatibility
- Old cpuIterations configurations continue to work unchanged
- TaskGenerator automatically detects CPU mode:
  1. cpuIterations > 0  → FIXED_ITERATION (old)
  2. targetMicros > 0   → DURATION_CONTROLLED (new)
  3. targetMillis > 0   → calibrate iterations (old)
